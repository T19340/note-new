# 그림 설계

## 1. 그림이 갖춰야 할 것

- **실측.** 화면의 모든 값은 `#note-data`의 데이터에서 그 자리에서 계산한다. 흉내 낸 그림은
  슬라이더를 움직이는 순간 들통나고, 한 번 들통나면 노트 전체가 의심받는다. 캡션의 수치도 같은
  데이터에서 나오게 해야 그림을 고치고 캡션을 안 고치는 사고가 없다.
- **묻는 것 / 볼 것.** 그림 머리에 두 줄을 단다. 이 그림이 묻는 질문과, 어디를 보면 답이
  보이는지. 조작이 있으면 "무엇을 움직이면 무엇이 변하는지"까지. 안내 없는 독자는 엉뚱한 곳을
  본다. 이 두 줄이 그림을 삽화에서 실험으로 바꾼다.
- **조작은 질문이 있을 때만.** 움직여 봐야 답이 보이는 질문이 없으면 슬라이더를 달지 않는다.
  목적 없는 조작 장치는 장난감이 되고, 진짜 발견 장치까지 장난감으로 보이게 한다.
- **색 계약.** 문서 첫머리에서 색의 의미를 선언하고 모든 그림이 지킨다. 무엇이 무슨 색인지는
  주제가 정한다(예: 회색=가진 것, 파랑=남의 몫, 주황=내 몫, 검정=늘림, 빨강=줄임).
- **캡션의 첫 문장이 결론.** 굵게 한 문장으로 그 그림의 메시지를 적고, 그 뒤에 수치를 든다.
  캡션마다 "무엇을 보아야 하는가" 같은 같은 라벨을 반복하지 않는다.
- **텍스트 상자와 화살표로 만든 흐름도는 그림이 아니다.** 글로 적은 표와 정보량이 같다. 공간·
  기하 정보가 본질이거나(곡선의 모양, 시간축), 수치 비교가 필요한 자리에만 그림을 쓴다.

## 2. 검증된 인터랙션 아홉 가지

두 편의 노트에서 실제로 쓰였고, `assets/js/common.js`의 엔진으로 재현할 수 있는 것들이다.
새 주제에서는 "무엇을 묻고 싶은가"로 고른다.

| 형태 | 언제 쓰나 | 구현 메모 |
|---|---|---|
| **단계 표** (stepper) | 절차가 누적되는 것을 보일 때. 거래 15건을 하나씩 적용하며 합계가 유지되는 것 | HTML 표를 다시 그리고, 방금 적용한 행에 `.now` 표시. 이전·다음·모두·처음부터 버튼 |
| **카드 퀴즈** | 분류 판단을 훈련할 때. "이 항목은 자산인가 부채인가", "어느 표에 있는가" | `common.js`의 `RSM.Quiz`. 카드 = 문항, 버튼 = 선택지, 오답에도 이유를 적는다 |
| **조립 퀴즈** | 두 가지를 함께 골라야 하는 판단. 분개의 차변·대변 | 선택지 목록 두 줄 + 확인 버튼. 어느 쪽이 틀렸는지 따로 알려 준다 |
| **T계정·장부 격자** | 기록이 두 곳으로 갈라져 쌓이는 구조 | `.tacc` 컴포넌트. 방금 전기한 칸을 주황으로, 관련 없는 계정은 흐리게 |
| **오류 시뮬레이터** | "이 오류는 검사에 걸리는가"를 묻을 때 | 오류를 데이터 변형으로 정의하고 결과를 다시 계산. 틀어진 줄을 빨강으로 |
| **폭포(다리) 그림** | 기초에서 기말로 가는 경로. 이익잉여금·현금의 이월 | `RSM.waterfall(캔버스, steps)`. `type:'bal'`은 잔액 막대, 나머지는 증감 |
| **시간선** | 현금과 인식처럼 두 사건의 시차를 볼 때 | 누적 계단선 두 개 + 음영이 곧 재무상태표 잔액. 연말에 세로 점선 |
| **산점도 + 등치선** | 두 지표의 관계와 경로. ROE와 부채비율, 같은 ROA 선 | 로그 눈금이 필요하면 좌표를 직접 log 변환. 마지막 점만 채우고 라벨은 점을 가리지 않게 |
| **역산 풀이기** | 빠진 값을 구하는 훈련 | "?"로 두고 "답 보기"로 식과 값을 함께 공개. 먼저 계산해 보라는 안내를 readout에 |

파라미터를 바꿔 함수의 거동을 보이는 **슬라이더 모형**(추정이 이익을 바꾸는 폭, 자사주 매입이
비율을 바꾸는 폭)은 위 표와 별개로 거의 모든 주제에서 쓸 수 있다. 곡선 + 현재 점 + readout의
조합이면 충분하다.

## 3. 데이터 계약

- 모든 숫자는 `data.json` 한 곳에 둔다. 본문·그림·게이트가 같은 파일을 본다.
- 조립기가 이것을 `<script type="application/json" id="note-data">`로 심고, `common.js`가
  `RSM.D`로 노출한다. 그림 코드는 데이터를 직접 적지 않는다.
- 그림 안에서 계산한 값이 본문 캡션에도 나오면, 그 값을 수치 게이트의 CLAIMS에 넣는다
  (`references/gates.md`). 그래야 나중에 데이터를 고쳤을 때 캡션이 따라오지 않는 사고를 잡는다.

## 4. 자주 밟는 지뢰

- **컨트롤 id와 섹션 id 충돌.** `f3-x` 같은 접두어를 쓴다. 섹션이 `s3`인데 컨트롤이 `s3`면
  `getElementById`가 헤딩을 잡아 readout이 NaN이 된다.
- **대문자 변환.** 셸의 `.figtag`, `표 머리글`, `summary`에 `text-transform:uppercase`가 걸려
  있어 `f(x)`가 `F(X)`로 보인다. 수식 기호가 든 라벨은 `text-transform:none`으로 덮는다.
- **전역 `svg{}` 규칙 금지.** 차트용 CSS를 전역에 쓰면 MathJax가 만든 수식 SVG까지 늘어난다.
  반드시 `.fig > svg`처럼 한정한다.
- **정사각 그림.** `square()`를 전체 폭 캔버스에 쓰면 그림이 구석으로 밀린다. 좁은 div로 감싼다.
- **토글 버튼 라벨은 "누르면 일어날 일"로.** 현재 상태를 적으면 캡션이 가리키는 버튼을 독자가
  찾지 못한다.
- **음수 표기.** 화면 문자열은 하이픈 대신 `−`(U+2212)로 통일한다. `common.js`의 `RSM.N`이
  처리한다.
